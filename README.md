# GameEyes — документация проекта

> Платформа для геймеров: верифицированная статистика из реальных API + поиск тиммейтов (LFG) + кланы + мировые лидерборды.
> Слоган: FIND. PLAY. WIN.

---

## 1. Что уже сделано (текущее состояние)

### Backend (Django + DRF)

**Авторизация**
- Вход через Steam OpenID, автосоздание `User` + `UserProfile` при первом входе
- Токен-авторизация для SPA (Vue не может работать через сессии, только через `Authorization: Token ...`)
- Автоматическое подключение Steam-аккаунта в `GameAccount` сразу при первом логине

**LFG (поиск тиммейтов)**
- Создание/просмотр/фильтрация заявок (по игре, поиску)
- Отклик на заявку, лимит на `slots_needed`, авто-закрытие когда набрано нужное число игроков
- Контакт автора скрыт от всех, кроме тех, кто откликнулся — раскрывается на 1 час (модель `ContactReveal`)
- Заявка автоматически пропадает из общей ленты через 1 час после времени начала события
- Чат по каждой заявке (модель `LFGChatMessage`), с аватарками участников
- Панель "Открытые контакты" — показывает раскрытые контакты, которые ещё не истекли

**Кланы**
- Создание клана (лимит 3 на юзера), вступление по коду приглашения
- Код приглашения виден **только лидеру** (не участникам, не гостям)
- Роли: leader / officer / member, лидер может менять роли и кикать участников (кроме себя)
- Дашборд активности: часы сегодня/неделя/месяц по каждому участнику, считается через diff между `DailySnapshot`

**Профили и верифицированная статистика**
Каждая платформа хранится как `GameAccount` (модель в `apps/profiles`), синк — через `ProfileSyncService` (`apps/profiles/serivces.py` — **да, с опечаткой в имени файла**, это исторически так и осталось, все импорты идут именно на `serivces`, не трогайте это без крайней необходимости):

| Платформа | Источник | Что даёт |
|---|---|---|
| Steam | Steam Web API | Часы по всем играм библиотеки, плюс расширенная официальная статистика CS2 (K/D, HS%, точность, MVP, топ-карты, любимое оружие) |
| OpenDota | OpenDota API (открытый) | Полная статистика Dota 2: винрейт, любимые герои, роль, GPM/XPM, история последних 8 матчей с деталями и списком **всех** участников матча |
| Faceit | Faceit API | CS2 через Faceit: винрейт, ELO, HS%, серии побед |
| LoL | Riot API | Ранг, LP, история матчей — **ключ Development истекает каждые 24 часа**, нужно регенерировать вручную на developer.riotgames.com |
| Valorant | HenrikDev (неофициальный community API) | Ранг, RR, агент, история матчей — работает, но не официальный Riot-канал |
| PUBG | TRN (tracker.gg developers) | K/D, винрейт — **ключ есть, но не активирован**, нужно попасть в whitelist через их Discord |
| Roblox | Roblox users API (официальный, но ограниченный) | Только профиль: друзья, подписчики, возраст аккаунта — **игровой статистики Roblox не публикует вообще ни для одной игры**, это не баг, а факт устройства платформы |

**Мировой лидерборд**
- `WorldLeaderboardView` — топ игроков даже без регистрации на GameEyes
- Dota 2: через `proPlayers` OpenDota, досортировано по `mmr_estimate` там где он открыт, кэш на 6 часов
- LoL: через официальный Riot Challenger league API
- Остальные игры — не реализовано, у большинства нет публичного мирового лидерборда

**Гостевые профили и участники матча**
- `GuestProfileView` — можно посмотреть статистику Dota-игрока, даже если он никогда не регистрировался на GameEyes
- `MatchParticipantsView` — по клику на матч показывает **всех** участников (не только тех, у кого публичный профиль), с аватарками через батч-запрос к Steam, полной статистикой (GPM/XPM/net worth/предметы/урон), уважает приватность (скрытые Steam-профили показываются анонимно, без утечки данных)

**Просмотры профиля**
- Счётчик просмотров `ProfileView` — не считает, если смотришь свой же профиль

### Frontend (Vue 3 + Pinia + Vue Router)

**Структура папок**
```
src/
├── api/               — axios-обёртки под каждый модуль (auth, lfg, clans, profiles)
├── assets/            — лого, будущие иконки игр
├── components/
│   ├── layout/        — Sidebar, TopBar, DashboardLayout
│   ├── lfg/           — карточки заявок, чат, модалка создания, GameSelect
│   ├── clans/         — карточки кланов, дашборд-таблица, модалки
│   ├── profiles/       — UniversalStatsCard, MatchHistoryTable, MatchParticipantsModal, GameAccountCard
│   └── chat/           — сайдбар со списком чатов
├── constants/          — список поддерживаемых игр
├── router/              — маршруты + guard на авторизацию
├── stores/              — Pinia: auth (токен, юзер), chat (непрочитанные + звук уведомлений)
└── views/                — страницы: Home, LFGFeed, ClanView, ProfileView, PublicProfileView, Login, AuthCallback
```

**Дизайн**
- Тёмная тема, акцент — красный (`#E63946`), шрифт Inter
- Единый компонент `UniversalStatsCard` — рендерит статистику **любой** платформы по одному формату (`metrics`, `badge`, `tags`, `list`, `match_history`) — при добавлении новой игры на бэке фронт трогать почти не нужно

## 2. Известные баги (актуально на сейчас)

1. **Публичный профиль `/players/{id}/` возвращает пустой ответ** — не диагностировано до конца, нужно смотреть Network-вкладку при заходе на чужой профиль
2. **"За неделю" в клан-дашборде часто пустая** — не баг кода, а нехватка данных: `DailySnapshot` пишется только при ручном нажатии ↻, если синков было мало, диффа за 7 дней просто не с чем считать
3. **Celery + Redis не работают на Windows** — при попытке асинхронной синхронизации через `.delay()` падает `redis.exceptions.ResponseError: unknown command 'HELLO'`. Сейчас `/sync/` работает **синхронно** внутри самого HTTP-запроса — это рабочий обходной путь, но не даёт делать автосинк по расписанию
4. Иконки игр — местами используются автогенерируемые цветные бейджи по инициалам (`getGameColor`/`getGameInitials` из `constants/games.js`), а не реальные SVG — часть игр (CS2, Dota2 и т.д.) уже имеет заготовленный механизм под `GAME_ICONS`, но сами файлы иконок ещё не до конца подключены

## 3. Задачи — от важного к менее важному

### 1. Починить Celery + Redis на Windows
```bash
pip install "redis==4.6.0"
pip freeze > requirements.txt
```
Запускать параллельно с `runserver`:
```bash
celery -A config worker -l info
celery -A config beat -l info
```
Это разблокирует автосинхронизацию раз в час (задача `sync_all_game_accounts` уже написана в `apps/profiles/tasks.py`, просто не может подключиться к брокеру). Без этого пункт 2 ниже не решить полностью.

### 2. Разобраться с пустым ответом на публичном профиле
Смотреть `PublicProfileView` в `apps/profiles/views.py` — возможно, `GameAccountSerializer` требует контекст, которого там не хватает, или сам `display_stats` падает молча на чужом аккаунте.

### 3. Получить рабочий доступ к PUBG API
Написать в Discord tracker.gg (ссылка на developers.tracker.gg), попросить whitelist для уже полученного ключа.

### 4. Получить Riot Personal API Key (не Development)
Development-ключ истекает каждые 24 часа — это неудобно для реального использования. Подать заявку через кабинет разработчика на Personal key.

### 5. Подключить реальные иконки игр
Файлы иконок кладутся в `src/assets/icons/games/`, подключаются через `GAME_ICONS` в `src/constants/games.js`. Используются в `GameIcon.vue` (LFG-карточки) и должны появиться в табах статистики профиля.

### 6. Улучшить расчёт времени в клан-дашборде
Текущая логика (`apps/clans/serivces.py` → `_period_activity`) считает честный дифф, но сильно зависит от плотности `DailySnapshot`. После пункта 1 (автосинк) стоит перепроверить точность за неделю/месяц с реальными накопленными данными.

### 7. Расширить мировой лидерборд на другие игры
Сейчас только Dota и LoL. Нужно поискать легальные открытые API с публичными топами для CS2/Valorant — большинство официальных API этого не даёт, придётся исследовать каждую игру отдельно.

### 8. Реальный realtime вместо polling в чате
Сейчас чат обновляется поллингом (`setInterval` каждые 4 сек во фронте). Проект уже использует `django-channels` в архитектуре — стоит перевести LFG-чат и уведомления на WebSocket.

### 9. Добавить тесты
Ни для одного модуля (`lfg`, `clans`, `profiles`, `users`) пока не написаны `tests.py`. Минимум — покрыть критичную логику: расчёт дневной активности, скрытие контакта, авто-закрытие LFG-постов.

### 10. Пагинация лент
`LFGFeedView`, список кланов — сейчас грузят всё разом. При росте данных нужна пагинация или infinite scroll.

## 4. Идеи фич на будущее (от меня, для обсуждения с командой)

1. **Push-уведомления в браузере** (Web Push API) — когда откликнулись на твою заявку, даже если вкладка закрыта
2. **Сравнение двух игроков side-by-side** — вводишь два ника, видишь таблицу их статистики рядом
3. **Достижения/бейджи GameEyes** — например "100 откликов", "Основатель клана", выдаются автоматически по действиям в самом приложении (не завязано на внешние API)
4. **Экспорт статистики матча как картинка** — для шеринга в соцсети/Discord (canvas-рендер карточки матча)
5. **Фильтр LFG по рангу/MMR** — раз у нас уже есть `skill_rating`, можно добавить в форму создания заявки минимальный требуемый ранг
6. **История собственных матчей на GameHub** — отдельная страница "мои матчи через LFG", не только внешняя статистика
7. **Клан-турниры** — простое бракетное дерево для внутриклановых состязаний
8. **Тёмная/светлая тема на выбор** — сейчас только тёмная, можно добавить переключатель
9. **Уведомления о новом сезоне ранга** (для Dota/LoL/Valorant) — напоминание синхронизироваться после ресета MMR
10. **API rate-limit dashboard для админа** — простая страница, показывающая, сколько запросов осталось до лимита у каждого внешнего API (полезно, когда подключим больше игроков)

## 5. Как запустить проект локально

### Backend

```bash
cd backend
python -m venv venv
venv\Scripts\activate          # Windows
pip install -r requirements.txt
```

Создать `.env` в `backend/` со всеми ключами:
```env
SECRET_KEY=...
DEBUG=True
DB_NAME=gamehub
DB_USER=gamehub
DB_PASSWORD=...
DB_HOST=localhost
DB_PORT=5432

REDIS_URL=redis://localhost:6379/0

STEAM_API_KEY=...
FACEIT_API_KEY=...
RIOT_API_KEY=...          # регенерировать каждые 24ч, пока не получен Personal key
VALORANT_API_KEY=...      # HenrikDev, через их Discord
TRN_API_KEY=...           # tracker.gg, для PUBG — пока не активирован
```

Запуск:
```bash
python manage.py migrate
python manage.py runserver
```

Для полной функциональности (автосинк) — два дополнительных терминала:
```bash
celery -A config worker -l info
celery -A config beat -l info
```

### Frontend

```bash
cd frontend
npm install
npm run dev
```
Открывается на `http://localhost:5173`, backend должен крутиться на `http://localhost:8000`.

## 6. Как работать с Git (шпаргалка)

### Один раз при начале работы
```bash
git clone <ссылка-на-репозиторий>
cd gamehub
```

### Каждый рабочий день
```bash
git checkout main
git pull origin main                    # подтянуть свежие изменения
git checkout -b feature/название-задачи # новая ветка под свою задачу
```

### После того как код готов
```bash
git add .
git commit -m "Короткое понятное описание что сделано"
git push origin feature/название-задачи
```
Дальше — создать Pull Request на GitHub, дождаться ревью, замёржить.

### Если словил конфликт
```bash
git checkout main
git pull origin main
git checkout feature/твоя-ветка
git merge main
```
Git покажет конфликтующие места (`<<<<<<<`, `=======`, `>>>>>>>`) — вручную выбираешь нужный вариант, убираешь маркеры, коммитишь:
```bash
git add .
git commit -m "Resolve merge conflict"
```

**Правило:** каждый работает в своей ветке над своим модулем (Паша — например, кланы/бэкенд, Егор — иконки/фронт-полировка), чтобы не пересекаться в одних и тех же файлах и не плодить конфликты на пустом месте.

## 7. Общие договорённости по коду

- Бэкенд-логика синхронизации живёт в `apps/profiles/serivces.py` (да, с опечаткой — так исторически сложилось, менять имя файла сейчас рискованно, слишком много импортов)
- Каждая новая игровая платформа добавляется по единому паттерну: клиент в `integrations/`, метод `_sync_<platform>()` в сервисе, ветка в `build_display_stats()`, запись в `PLATFORM_CHOICES` модели
- Фронт для новой статистики почти всегда **не требует** нового Vue-компонента — `UniversalStatsCard` универсален, если бэкенд отдаёт данные в правильном формате (`metrics`/`badge`/`tags`/`list`/`match_history`)
- Приватность — если платформа может отдать личные данные стороннего человека (как в участниках матча), всегда проверяем: юзер зарегистрирован на GameEyes → показываем реальное имя и делаем кликабельным; юзер публичный, но не наш → показываем его открытое имя без клика; юзер скрыл профиль → показываем анонимно, без утечки
